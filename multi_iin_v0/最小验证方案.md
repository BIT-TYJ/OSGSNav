# Sequential Ordered Multi-IIN v0 最小验证方案

## 1. 本轮只验证一个假设

第一目标执行期间获得的环境信息，是否能降低第二目标的导航成本。

本轮不验证多目标联合感知、目标自主排序、同类目标辨识或
Multi-Target SWMI。它们只有在共享状态本身有效后才进入下一阶段。

## 2. 固定任务协议

每个 episode 包含两个有序目标 `g1 -> g2`：

1. 从统一起点启动，只向策略提供 `g1` 的目标图像。
2. 对 `g1` 调用中间 STOP，表示声明当前目标。
3. 记录 `g1` 成功或失败，不重置 simulator pose。
4. 将策略可见目标切换为 `g2`。
5. 对 `g2` 完成相同流程，随后结束整个 episode。

每个目标最多 1000 step，成功距离为 1.0 m。错误 STOP 或当前目标超时
只结束当前目标，不阻止评测下一个目标，以便保留部分成功和第二目标成本。

策略只能看到当前目标 RGB 图像。以下字段只允许 evaluator 使用：

- `object_category`
- `goal_object_id`
- `view_points`
- `oracle`

目标类别必须由目标图检测得到，不能直接读取数据集类别标签。

## 3. 当前开发 manifest

文件：`manifests/miin_v0_val_k2.json`

- 来源：Habitat 2023 InstanceImageNav、HM3D-v3 val。
- 场景数：5。
- 每场景 episode：20。
- 总 episode：100。
- 每个 episode 的两个目标实例不同、类别不同。
- 目标间距离：near 37、medium 34、far 29。
- ordered oracle 路径中位数：12.89 m。
- ordered oracle 路径范围：2.67–39.70 m。

这只是生命周期和复用假设开发集，不作为最终论文 benchmark。当前类别仍受源数据
分布影响，chair 比例偏高；正式 benchmark 需要增加类别/实例使用次数分层采样。

## 4. 三组必要对照

所有方法使用同一批 episode、相同目标顺序、相同单目标预算和成功判定。

### A. Independent-Reset

对 `g1`、`g2` 分别从 episode 原始起点运行：

- 重置机器人位置；
- 清空 2D map；
- 清空 3DGS；
- 清空历史帧和候选状态。

这是“独立执行两次单目标 IIN”的参考。

### B. Continuous-Clear

从 `g1` 切换到 `g2` 时：

- 保留机器人实际位置；
- 清空 2D map、3DGS、历史帧和目标状态。

它控制连续路线和第一目标结束位置带来的优势。

### C. Continuous-Shared

从 `g1` 切换到 `g2` 时：

- 保留机器人位置；
- 保留 2D occupancy/exploration map；
- 保留 3DGS 和历史 RGB-D 帧；
- 保留碰撞、visited 和 frontier 历史；
- 清空上一目标专属的候选、匹配计数、确认状态和局部导航目标。

`C - B` 才是本轮对共享地图收益的主要因果对照。`C - A` 同时包含连续路线收益，
不能单独解释为 Map Reuse Gain。

## 5. 最小记录格式

每个方法、每个 episode 至少记录：

```json
{
  "episode_id": "miin_v0_val_000000",
  "variant": "Continuous-Shared",
  "goals": [
    {
      "order": 0,
      "success": true,
      "path_length_m": 8.2,
      "steps": 326,
      "wall_time_s": 410.5
    },
    {
      "order": 1,
      "success": true,
      "path_length_m": 4.1,
      "steps": 172,
      "wall_time_s": 221.0
    }
  ]
}
```

失败目标仍记录实际消耗，不能把失败样本从成本统计中删除。

## 6. 第一轮指标

### 6.1 正确性

- `GSR = 成功目标数 / 200`
- `All-Goal Success = 两个目标都成功的 episode 数 / 100`
- 分别报告第一目标和第二目标成功率。

### 6.2 第二目标边际成本

- 第二目标平均路径长度；
- 第二目标平均 step；
- 第二目标平均墙钟时间；
- 第二目标匹配/定位触发次数。

上述指标对所有 episode 统计；成功样本条件均值可以附加报告，但不能替代全样本均值。

### 6.3 共享收益

分别对路径、step 和时间计算：

```text
ReuseGain = (Continuous-Clear - Continuous-Shared) / Continuous-Clear
```

必须先按 episode 配对，再报告均值、bootstrap 95% 置信区间和 paired significance。

## 7. P0 数据通过条件

- manifest 结构和 200 个源目标引用全部有效；
- 两个目标的 `goal_image_id` 均在源目标图范围内；
- 从统一起点到两个目标均可达；
- 第一目标到第二目标可达；
- 100 个 episode 的 oracle 数值可独立重算且误差不超过 `1e-4 m`；
- 相同 seed 重复生成字节级一致。

当前 manifest 已满足以上数据条件。

## 8. P1 运行实验通过条件

先运行 10 个 episode 做生命周期 smoke test：

- 中间 STOP 不重置场景或机器人位姿；
- `g2` 图像切换正确；
- evaluator 只按当前目标实例判断成功；
- `Continuous-Clear` 确实清空共享状态；
- `Continuous-Shared` 的地图、3DGS 和历史帧连续；
- 原单目标 IIN 入口和结果完全不受影响。

随后运行完整 100 episode。若 `Continuous-Shared` 相对 `Continuous-Clear` 的第二目标
路径或 step 有稳定下降，且 GSR 不降低，则进入“所有目标图从开始可见”的 Ordered
Multi-IIN v1。若没有收益，先分析 2D map、3DGS 和历史帧分别是否被第二目标实际复用，
不立即开发目标调度和 Multi-Target SWMI。

## 9. 当前 oracle 的边界

当前 `ordered_length_m` 使用合法 view-point 中心计算：

```text
min over v1 in V1, v2 in V2: d(start, v1) + d(v1, v2)
```

它保证两个路径段使用一致的第一目标落点，但尚未把 view point 周围 1.0 m 的完整成功
区域纳入最优化，因此可能略微高估真正的最短成功路径。该值适合 v0 可达性验证和难度
分层；正式 Tour-SPL 前应再实现 success-region oracle。
